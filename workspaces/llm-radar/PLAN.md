## 1. 目标与明确边界

在 OpenMontage/workspaces/llm-radar 维护可复用的成片组装代码，各期资源存放于 video_projects/llm-radar。OpenMontage 接收 LLM Radar 提供的动画片段、图片、音效、音乐和相关信息，按每期配置组装成完整视频。

这里的“模板”指成片结构、镜头顺序、转场、文字叠加和混音规则，不是雷达动画生成模板。

| 工作 | 负责方 |
| --- | --- |
| 模型数据采集、整理、来源、归一化和评分口径 | LLM Radar |
| 雷达动画代码、动画参数、动画生成与片段导出 | LLM Radar |
| 图片、品牌素材、字体、音效、音乐及来源授权管理 | LLM Radar |
| 每期素材选择、剪辑顺序、片头片尾、字幕、转场、音画编排 | OpenMontage |
| 完整视频组装、最终编码、质量检查与成片归档 | OpenMontage |

不迁入、复制或重写 RadarMaster、雷达动画脚本及其运行依赖；不在 OpenMontage 增加雷达生成器或雷达专用 Remotion composition。上游生成动画片段，下游渲染最终成片。

## 2. 素材交接约定

OpenMontage 只读接收上游交付清单，复制本期需要的媒体和元数据为固定快照，不调用上游雷达生成脚本。所需片段不存在或不匹配时，形成明确的补充素材清单，由 LLM Radar 生成后再导入。

### 动画片段清单

每个片段至少提供：

- 唯一 clipId、相对路径、文件指纹、版本及生成日期。
- 当前模型 ID、上一模型 ID（如有残影）、六轴顺序、数据/尺度版本或指纹、正式/草稿/演示状态。
- 分辨率、帧率、时长、编码、是否有透明通道、是否包含音频。
- 内嵌音频是音效、音乐还是混合音轨；哪些声音允许在下游追加。
- 可用裁切区间、动画完成时间、可停留区间（如上游能提供）。
- 来源和署名要求；片段中已经烧录的标题、模型编号等内容说明。

重要约束：上一模型残影已烘焙到片段中，改变播放顺序可能需要上游重新导出。例如 A→B 片段不能不加检查地用在 C 后面。编号、总模型数、标题等已烧录内容也须与本期一致。OpenMontage 不通过改动画代码来修正这些问题。

### 其他素材

图片、字体、音乐、独立音效提供素材 ID、相对路径、文件指纹、来源、授权与署名信息。复用上游已有 manifest，缺失字段在交接阶段补齐，不建立第二套素材主库。

每期导入时检查路径不得逃逸出源目录，媒体可解码，文件指纹一致。源目录后续更新不会悄悄改变已归档的一期。

## 3. 组装模板与第一版范围

建议默认输出 1920×1080、60 fps 横屏 MP4，最终以交付片段规格和用户确认的成片要求为准。

成片结构：可选片头 → 按配置排列的雷达动画片段 → 可选说明/总结 → 来源与署名片尾。

每期配置包括：

- 标题、期号、日期、片段 ID 和顺序。
- 合法入出点、镜头衔接方式、段间过渡、片头片尾及字幕内容。
- 音乐和独立音效 ID、音量、淡入淡出、音轨保留或静音策略。
- 输出规格、草稿/正式模式、输出文件名。

不在组装时重算分数、改变顶点动画或拉伸动画速度。阅读时间不足时，优先使用已提供的停留区间；需要额外定格须在方案中说明，或要求上游提供更长片段。

第一版优先使用带背景的动画片段直接剪辑。透明片段叠加为可选能力，需先验证实际 Alpha 解码与合成路径，不作为默认依赖。旁白、竖屏、自动发布不在第一版默认范围。

## 4. 声音处理

素材清单必须标记片段已带入的声音，避免同一套音效重复播放。

- 带动画同步音效的片段：默认保留原音效，只追加本期音乐及明确需要的外部音效。
- 无声片段：按上游提供的声音 cue 信息配置独立音效。
- 已混合音乐与音效的片段：不假设能够分离；如需独立混音，向上游索取分轨或无背景音乐版本。
- 裁切、转场时同步处理原音轨；检查音效触发、淡出、断尾和峰值。

## 6. OpenMontage 流程与工具

采用素材驱动的 hybrid 管线：先审阅现有媒体，再进入 idea、script、scene_plan、assets、edit、compose；发布为独立可选阶段。这里的 assets 阶段负责接收、验证和准备已有素材，不承担雷达动画生成。

优先复用 video_stitch、audio_mixer、video_compose 完成剪辑、混音和最终编码。第一版以 FFmpeg 组装路径为候选，实际能力须在实施 preflight 核验；计划不等于已经验证可运行。

片头片尾或叠字若需要其他合成引擎，在提案阶段比较实际可用选项并记录决定；即使使用 Remotion 或 HyperFrames，也只用于包装和组装，不接管雷达动画。

取消旧计划中的项目级雷达渲染注册、RadarMaster 迁移和雷达运行依赖隔离工作。除非现有工具在具体组装验收中发现缺口，否则不改公共渲染架构。

所有实际生产仍读取对应 director skill、遵循检查点及质量门禁；不另写绕过管线的生产状态机。

## 7. 实施顺序

| 阶段 | 工作 | 验收 |
| --- | --- | --- |
| 1. 盘点交付 | 盘点现成动画、图片、声音，定义素材清单和每期配置 | 能明确识别一个片段的模型、前驱、数据版本、时长和音轨 |
| 2. 导入校验 | 按期复制所需媒体、验证指纹和媒体属性、核对顺序 | 不改上游；缺素材、错误前驱、错误版本有明确报告 |
| 3. 组装规则 | 配置片头片尾、片段顺序、字幕、转场及声音策略 | 三片段时间线可审阅，无雷达生成代码或依赖 |
| 4. 样片合成 | 经现有管线组装并输出完整样片 | 全片播放正常，时长与时间线一致，无重复音效 |
| 5. 验收与复用 | 检查画面、声音、来源及输出规格，完善说明 | 换成另一组兼容片段仅改配置，不改组装源码 |

依赖顺序：交付格式 → 导入校验 → 组装配置 → 样片 → 验收。缺少动画或需改变动画内容时，把所需模型对、规格、时长等交给 LLM Radar 补充。

## 8. 验证与完成标准

重点检查：

- 所需片段和其他素材均存在、可解码、指纹匹配；当前模型与上一模型顺序正确。
- 数据尺度一致，画面中烧录的标题/编号与本期配置一致；草稿或演示片段不得冒充正式评测。
- 当前上游数据仍有 draft/renderReady=false；正式组装沿用上游就绪状态检查，预览明确标记草稿或演示。
- 各片段分辨率、帧率、音频参数不一致时，先确定统一策略，再验证结果；不静默改变关键视觉内容。
- 转场不遮挡关键数值，不提前截掉展开与锁定；叠字不重复覆盖片段已有标识。
- 音效没有重复，音乐衔接自然，原音轨与动画保持同步。
- ffprobe 检查成片分辨率、帧率、时长及音轨；人工审阅关键帧并试听转场。

如需新增脚本，使用 pnpm/uv 和现有测试习惯；确定性导入与校验逻辑和创意编排分开，接口以明确的 clipId/assetId 引用素材。

完成标准：LLM Radar 继续拥有并生成所有雷达动画；OpenMontage 无需访问其动画源码或安装其动画依赖，仅凭交付的媒体、元数据和每期配置即可完成组装、最终渲染和归档。新增一期如需要不同动画，应先由上游提供对应片段，再由下游复用同一组装模板。
